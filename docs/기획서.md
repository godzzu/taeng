# 1. 프로젝트 개요

## 1.1 프로젝트 목적

HTML, CSS, JavaScript를 이용하여 직접 제작하고 운영할 수 있는 모바일
청첩장을 개발한다.

하나의 공통 웹 구조에 2가지 디자인 템플릿을 적용하여, 설정 파일의 템플릿
ID만 변경하면 청첩장 전체 디자인이 변경되도록 구현한다.

청첩장에 포함되는 신랑·신부 정보, 예식 일정, 장소, 사진, 계좌번호,
연락처 등의 정보는 별도 설정 파일에서 관리한다.

## 1.2 핵심 개발 목표

  구분       목표
  ---------- --------------------------------------------
  디자인     2가지 독립적인 디자인 템플릿
  구조       단일 페이지, 8개 섹션
  콘텐츠     JSON 또는 JS 설정 파일로 분리
  기능       갤러리, 지도, 계좌복사, 연락, 방명록, 공유
  반응형     모바일 우선 설계
  개발       HTML, CSS, JavaScript
  배포       GitHub Pages
  유지보수   섹션별 모듈화 및 템플릿 확장 가능 구조

## 1.3 프로젝트 범위

**포함** - 청첩장 메인 화면 - 초대 문구 - 예식 정보 - 사진 갤러리 - 지도
및 길찾기 - 계좌번호 안내 및 복사 - 전화 및 문자 연결 - 방명록 -
카카오톡 공유 - 2가지 디자인 템플릿 - 설정 파일을 통한 콘텐츠 관리

**제외** - 회원가입 및 로그인 - 별도 관리자 웹사이트 - 온라인 RSVP 및
참석 여부 관리 - 결제 기능 - 자체 서버 구축

# 2. 디자인 및 템플릿 설계

## 2.1 템플릿 관리 방식

템플릿은 `templateId`를 기준으로 선택한다.

  -----------------------------------------------------------------------
  템플릿 ID               템플릿 이름             디자인 컨셉
  ----------------------- ----------------------- -----------------------
  `wedding-floral`        Floral Pastel           파스텔 블루·그린, 꽃,
                                                  자연스러운 감성

  `wedding-sketch`        Minimal Sketch          블랙&화이트, 손그림,
                                                  손글씨
  -----------------------------------------------------------------------

설정 파일에서 다음과 같이 템플릿을 지정한다.

``` javascript
// config/wedding.config.js
export const weddingConfig = {
  templateId: "wedding-floral"
};
```

템플릿 변경 시 `wedding-sketch`로 변경하면 전체 디자인이 전환된다.

## 2.2 디자인 1: Floral Pastel

**디자인 방향** - 연한 파스텔 블루, 세이지 그린, 아이보리 - 꽃과 식물을
활용한 자연스러운 디자인 - 수채화 느낌의 꽃 일러스트 - 부드럽고 우아한
분위기 - 여백을 넉넉하게 사용 - 얇고 섬세한 서체 - 곡선형 장식과 꽃잎
형태의 디테일

**색상 가이드**

  용도         컬러
  ------------ -----------
  Primary      `#AFC8D9`
  Secondary    `#B9CCBA`
  Background   `#FAFAF5`
  Text         `#58666B`
  Accent       `#D9E6E2`
  Sub Accent   `#E9DCD7`

**이미지 폴더**

`assets/images/templates/floral/`

-   `floral-main.jpg`: 메인 배경 이미지
-   `floral-frame.png`: 꽃 장식 프레임
-   `floral-divider.png`: 섹션 구분 장식
-   `floral-decoration-01.png`: 꽃 일러스트
-   `floral-decoration-02.png`: 잎사귀 일러스트

이미지는 직접 제작하거나 별도 이미지 폴더에 저장한 참고 이미지를
사용한다. 참고 이미지와 실제 배포용 이미지는 저작권 및 사용 허가를
확인한다.

## 2.3 디자인 2: Minimal Sketch

**디자인 방향** - 흑백 중심의 미니멀 디자인 - 손으로 그린 듯한 꽃, 하트,
반지 일러스트 - 손글씨 느낌의 타이포그래피 - 종이에 직접 작성한 듯한
레이아웃 - 불필요한 장식 최소화 - 얇은 검정색 선과 자연스러운 스케치 -
빈티지하고 감성적인 분위기

**색상 가이드**

  용도         컬러
  ------------ -----------
  Primary      `#222222`
  Secondary    `#777777`
  Background   `#FFFFFF`
  Text         `#333333`
  Border       `#D8D8D8`
  Accent       `#F4F4F4`

**이미지 폴더**

`assets/images/templates/sketch/`

-   `sketch-main.jpg`: 메인 배경 이미지
-   `sketch-flower.png`: 손그림 꽃
-   `sketch-heart.png`: 손그림 하트
-   `sketch-ring.png`: 반지 일러스트
-   `sketch-divider.png`: 손그림 구분선

이미지는 직접 제작하거나 별도 이미지 폴더에 저장한 참고 이미지를
사용한다.

## 2.4 템플릿 적용 아키텍처

템플릿별 HTML을 별도로 만들지 않는다. 공통 HTML 구조를 사용하고 CSS
변수와 템플릿별 스타일 클래스를 변경한다.

``` javascript
// js/core/theme.js
export function applyTheme(templateId) {
  const validTemplates = [
    "wedding-floral",
    "wedding-sketch"
  ];

  const selectedTemplate = validTemplates.includes(templateId)
    ? templateId
    : "wedding-floral";

  document.documentElement.dataset.theme = selectedTemplate;
}
```

``` css
:root[data-theme="wedding-floral"] {
  --color-primary: #AFC8D9;
  --color-secondary: #B9CCBA;
  --color-background: #FAFAF5;
  --color-text: #58666B;
  --color-accent: #D9E6E2;
}

:root[data-theme="wedding-sketch"] {
  --color-primary: #222222;
  --color-secondary: #777777;
  --color-background: #FFFFFF;
  --color-text: #333333;
  --color-accent: #F4F4F4;
}
```

템플릿별 폰트, 테두리, 배경 이미지, 장식 이미지, 버튼 스타일도 CSS 변수
또는 테마별 CSS 파일로 관리한다.

# 3. 전체 페이지 및 섹션 설계

## 3.1 페이지 구성

전체 페이지는 하나의 HTML 페이지에 8개 섹션으로 구성한다.

  순서   섹션 ID          섹션명           주요 기능
  ------ ---------------- ---------------- ----------------------------------------
  01     `hero`           첫 화면          신랑·신부 이름, 메인 이미지, 예식 날짜
  02     `invitation`     초대 문구        초대 메시지, 부모님 성함
  03     `wedding-info`   날짜 및 장소     예식 일시, 장소, D-day
  04     `gallery`        사진 갤러리      썸네일, 모달 확대, 이전/다음
  05     `location`       오시는 길        지도, 주소, 길찾기
  06     `account`        마음 전하실 곳   계좌정보, 원터치 복사, 토스트
  07     `contact`        연락하기         신랑·신부 및 양가 부모님 전화·문자
  08     `guestbook`      방명록           축하 메시지 작성 및 조회

카카오톡 공유 기능은 특정 섹션에 종속시키지 않고 공통 공유 버튼으로
제공한다. 첫 화면, 하단 또는 방명록 아래에 배치할 수 있다.

## 3.2 섹션별 상세 기획

### SECTION 01. 첫 화면 (Hero)

**목적:** 방문자가 청첩장에 접속했을 때 가장 먼저 보는 메인 화면.

**구성 요소** - 메인 커버 이미지 - 신랑 이름 - 신부 이름 - 결혼 날짜 -
예식 장소 간략 정보 - 메인 장식 일러스트 - 아래로 스크롤 유도 아이콘

**디자인** - Floral: 파스텔 배경 + 꽃 장식 + 수채화 이미지 - Sketch:
흰색 배경 + 손그림 일러스트 + 손글씨 타이포그래피

**기능** - 첫 화면 페이드인 애니메이션 - 스크롤 유도 - 날짜 정보 설정
파일 연동

### SECTION 02. 초대 문구 (Invitation)

**구성 요소** - 섹션 제목 - 초대 문구 - 신랑·신부 이름 - 양가 부모님
성함 - 관계 표현(장남, 장녀 등) - 장식 이미지

**기능** - 설정 파일의 초대 문구 표시 - 줄바꿈 유지 - 텍스트 중심의
감성적인 레이아웃

### SECTION 03. 날짜 및 장소 (Wedding Info)

**구성 요소** - 예식 날짜 - 요일 - 예식 시간 - 예식장 이름 - 층 및 홀
이름 - 주소 - D-day 카운트다운

**기능** - 예식 날짜 및 시간 자동 계산 - 날짜 정보 표시 - 일정 추가
기능은 확장 기능으로 고려

날짜와 시간은 한국 시간 기준으로 처리하고, 날짜 문자열을 단순 파싱할 때
발생할 수 있는 시간대 오차를 방지하도록 구현한다.

### SECTION 04. 사진 갤러리 (Gallery)

**구성 요소** - 썸네일 이미지 그리드 - 이미지 확대 모달 - 닫기 버튼 -
이전 이미지 / 다음 이미지 버튼 - 현재 이미지 번호

**기능** - 썸네일 클릭 시 모달 확대 - 좌우 버튼으로 이미지 전환 - ESC
키로 모달 닫기 - 모바일 터치 스와이프 지원 - 이미지 로딩 지연 처리(Lazy
Loading) - 모달 열림 중 배경 스크롤 잠금 - 모달 종료 시 포커스 원위치
복귀

이미지는 설정 파일에 경로만 등록한다.

``` javascript
gallery: [
  {
    id: 1,
    src: "./assets/images/gallery/photo-01.jpg",
    alt: "웨딩 사진 1"
  }
]
```

### SECTION 05. 오시는 길 (Location)

**구성 요소** - 지도 - 예식장 이름 - 주소 - 대중교통 안내 - 주차 안내 -
길찾기 버튼

**기능** - 지도 표시 - 카카오맵 또는 네이버 지도 연결 - 길찾기 링크 -
주소 복사 기능은 선택적으로 추가

**구현 방식** - 지도 SDK 또는 지도 임베드 사용 - 길찾기는 외부 지도
서비스 URL로 연결 - 지도 API 키는 공개 가능한 클라이언트 키만 사용하고
도메인 제한 설정

### SECTION 06. 계좌 안내 (Account)

**구성 요소** - 신랑 측 계좌정보 - 신부 측 계좌정보 - 예금주 - 은행명 -
계좌번호 - 복사 버튼

**기능** 1. 계좌번호 복사 2. 복사 성공 시 토스트 표시 3. 복사 실패 시
오류 메시지 표시 4. 여러 계좌정보 개별 복사

**토스트 문구 예시** - 계좌번호가 복사되었습니다. - 복사에 실패했습니다.
다시 시도해주세요.

계좌정보 노출 여부를 설정 파일에서 제어하고 불필요한 개인정보 노출을
방지한다.

### SECTION 07. 연락하기 (Contact)

**구성 요소** - 신랑 연락처 - 신부 연락처 - 신랑 측 부모님 연락처 - 신부
측 부모님 연락처

**기능** - 전화 연결: `tel:` - 문자 연결: `sms:` - 연락처 표시 여부
설정 - 모바일 기기에서 기본 전화 및 문자 앱 실행

### SECTION 08. 방명록 (Guestbook)

**구성 요소** - 축하 메시지 작성 영역 - 작성자 이름 - 메시지 입력 -
비밀번호 또는 인증 수단(삭제 기능을 제공하는 경우) - 메시지 목록 - 작성
날짜 - 삭제 기능(작성자 본인 인증 등)

**기능** - 메시지 등록 - 메시지 조회 - 입력값 검증 - 글자 수 제한 - XSS
방지 - 비속어 및 스팸 방지 고려

**기술적 결정**

GitHub Pages는 정적 호스팅이므로 자체적으로 방명록 데이터를 저장할 수
없다. 다음 중 하나를 연동한다.

1.  Supabase: 데이터베이스 및 API 제공
2.  Firebase: Firestore 기반 데이터 저장
3.  Google Apps Script: Google Sheets 기반 저장

권장 방식은 Supabase 또는 Firebase다. 프론트엔드 코드에 관리자
비밀번호를 저장하거나 브라우저 로컬 저장소만으로 실제 방명록을 구현하는
방식은 사용하지 않는다.

# 9. 추가 개발 시 반드시 지켜야 할 규칙

AI 코딩 도구를 사용할 때 다음 내용을 공통 개발 규칙으로 전달한다.

1.  기존 프로젝트의 폴더 구조를 임의로 변경하지 않는다.
2.  기존에 구현한 기능을 제거하거나 축약하지 않는다.
3.  섹션별 JavaScript는 독립적으로 동작하도록 구현한다.
4.  모든 콘텐츠는 `wedding.config.js`에서 가져온다.
5.  템플릿별 스타일은 별도 CSS 파일에서 관리한다.
6.  공통 기능은 `js/core` 또는 `js/services`에서 관리한다.
7.  외부 API 호출을 화면 렌더링 코드에 직접 작성하지 않는다.
8.  모바일 화면을 우선으로 개발한다.
9.  새 파일을 생성할 때 기존 프로젝트와의 연결 관계를 설명한다.
10. 각 개발 단계가 끝날 때 브라우저에서 확인할 테스트 항목을 제공한다.

**최종 개발 원칙**

콘텐츠는 설정 파일에서, 디자인은 템플릿 CSS에서, 기능은 섹션별
JavaScript에서 관리한다.

이 원칙을 지키면 향후 다음과 같은 확장이 가능하다.

-   세 번째, 네 번째 디자인 템플릿 추가
-   다른 커플의 청첩장으로 재사용
-   사진과 문구만 변경하여 새로운 청첩장 제작
-   관리자 페이지 추가
-   참석 여부 확인 기능 추가
-   일정 추가 기능 추가
-   방명록 관리 기능 추가

프로젝트의 최종 목표는 한 번 사용할 청첩장을 만드는 것에 그치지 않고,
설정 파일과 템플릿만 변경하면 여러 종류의 청첩장을 재사용해서 만들 수
있는 개인용 모바일 청첩장 플랫폼을 구축하는 것이다.

# 11. 추가 기술적 고려사항

## 11.1 방명록 저장소

GitHub Pages는 정적 호스팅이므로 방명록 저장을 위해 Supabase 또는
Firebase 같은 외부 데이터베이스가 필요하다. 클라이언트에 관리자
비밀번호나 서비스 비밀키를 저장하지 않는다.

## 11.2 카카오톡 공유 썸네일

`wedding.config.js`의 썸네일 경로는 카카오 공유 메시지에 활용할 수
있지만, 일반 URL 미리보기에는 Open Graph 메타태그도 필요하다. GitHub
Pages는 정적 HTML을 제공하므로 템플릿 변경에 따라 공유 미리보기 이미지가
자동으로 바뀌는 구조는 아니다. 템플릿별 OG 이미지 또는 별도 정적 공유
페이지를 고려한다.

## 11.3 이미지 에셋

디자인을 변경할 때 CSS를 다시 작성하는 대신 이미지 경로와 CSS 변수만
변경할 수 있도록 구성한다. 이미지 자체의 라이선스와 사용 허가도
확인한다.

# 12. 최종 개발 전략

개발은 다음 3단계로 나누어 진행한다.

## 1단계. 디자인 및 기본 구조

-   프로젝트 폴더 생성
-   설정 파일 생성
-   2가지 템플릿 개발
-   8개 섹션의 공통 레이아웃 개발

## 2단계. 개별 기능 개발

-   갤러리 및 모달
-   지도 및 길찾기
-   계좌 복사 및 토스트
-   전화 및 문자
-   방명록 및 카카오톡 공유

## 3단계. 통합 및 배포

-   모바일 반응형 검증
-   템플릿별 전체 디자인 점검
-   외부 API 연동 테스트
-   GitHub Pages 배포

**가장 중요한 권장 사항:** 처음부터 8개 섹션을 한꺼번에 개발하지 말고,
공통 구조와 두 가지 테마를 먼저 완성한 다음 섹션을 하나씩 추가한다. 각
단계마다 실제 브라우저에서 확인하고 다음 단계로 넘어가면 AI 코딩 도구를
사용하더라도 기존 기능이 무너지는 문제를 줄일 수 있다.
